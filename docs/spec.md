## I. 논문 분석 및 요약
기본적으로 Moonlight AI의 방식과 유사한 방향으로 기능을 제작할 예정
https://www.themoonlight.io/ko/features

**0. Paper Reader**
- arXiv HTML과 PDF를 모두 지원하고, 상단 버튼으로 전환 가능(전환해도 읽던 섹션 위치 유지)
- 원문 확보 순서: arXiv 공식 HTML → ar5iv → arXiv LaTeX 원본을 LaTeXML로 직접 변환 → Semantic Scholar/OpenAlex로 같은 논문의 arXiv 판 탐색 → 모두 없으면 PDF만 사용
- HTML이 없는 논문은 PDF로 열고, HTML 전환 버튼은 비활성화한 뒤 "HTML 없음"으로 안내
- PDF는 내장 텍스트 레이어로 문장 선택·하이라이트·좌표를 처리하고, 섹션 구조·참고문헌·본문 인용 위치는 GROBID와 PyMuPDF로 추출
- 스캔본처럼 텍스트 레이어가 없는 PDF는 업로드 시 감지해 OCR(ocrmypdf)로 텍스트 레이어를 먼저 추가
- 수식은 HTML의 MathML → LaTeX 원본 순으로 가져오고, PDF만 있으면 수식 영역을 이미지로 잘라 AI가 읽도록 처리
- PDF 보기는 쪽 이동, 확대/축소, 폭 맞춤 지원
- 리더 화면은 왼쪽 AI 아웃라인, 가운데 본문, 오른쪽 AI 패널(요약 / 채팅 / 인용 / 노트) 3단 구성이며, 양쪽 패널은 크기 조절과 접기 가능

**1. Explanation**
- 이해하기 어려운 문장이나 수식을 선택하면 AI가 알기 쉽게 개념과 맥락을 차근차근 설명
- 표, 이미지, 수식 등 시각 자료도 AI가 자세하게 설명
- 논문 제목과 각 섹션 제목 옆 AI 버튼(단축키 E)으로 해당 섹션 설명 요청
- 그림·수식에 마우스를 올리면 "풀어서 설명받기"와 복사(수식은 LaTeX) 버튼 표시
- 설명은 본문 위에 떠 있는 대화창으로 표시하며, 이어서 질문하기, 추천 후속 질문(생각 확장하기), 관련 논문(라이브러리에 있으면 표시), 용어 풀이(용어에 마우스를 올리면 뜻 표시) 제공
- 대화창은 크기 조절, 지우기, 최소화 가능하며, 최소화하면 설명을 요청한 위치 바로 아래에 제목만 보이는 작은 버튼으로 접힘
- Hallucination 방지를 위해 원문 위치 링크 또는 근거 표시 필수

**2. Text Selection Menu**
- 본문 텍스트를 선택하면 설명(E) / 인포그래픽(I) / 하이라이트(H) / 번역(T) / 주석(C) / AI에게 질문(Enter) 메뉴 표시
- 번역은 선택한 부분만 한국어로 보여주며, 페이지 전체 번역 기능은 두지 않음
- 하이라이트와 주석은 노트에 모아 보관

**3. Auto Highlight**
- 논문의 핵심 혁신, 방법, 결과를 AI가 자동으로 하이라이트하고, 사용자 메모와 함께 종류별로 켜고 끌 수 있음
- 본문과 표의 수치가 서로 다른 경우 "확인 필요"로 표시하고, 재현 목표로 쓸 값을 사용자가 선택하면 요약 MD에 기록
- 아웃라인의 각 섹션 옆에 해당 섹션의 하이라이트 종류를 표시

**4. Summary**
- 논문 3줄 요약, Abstract/Dataset/Method/Result/Limitation으로 논문을 간단하게 요약 정리
- MD 파일로 Journal Name, Authors, Publication Date, Research Field, Base Model, Paper URL, Code Source과 요약한 Abstract, Dataset, Method, Result, Limitation, Citations & Links를 저장 가능
- OpenReview에 있는 논문일 경우, 리뷰 요약을 확인하여 Limitation에 반영(반드시 출처 표기)
- 저장한 MD 파일은 Notion이나 Obsidian에 호환되도록 작성하며, 원문 위치는 Obsidian 페이지 링크와 텍스트 표기를 함께 기재
  - arXiv HTML: `[[논문.html#S4.SS1|§4.1]]`
  - PDF: `[[논문.pdf#page=5]] · p.5, §4.1`
- 요약은 "정리된 보기"와 "MD 원문"으로 전환해 볼 수 있으며, MD 원문은 화면에서 바로 수정·저장 가능
- 원문에서 확인하지 못한 값은 추측하지 않고 `[대괄호 자리표시]`로 남김
- Hallucination 방지를 위해 원문 위치 링크 또는 근거 표시 필수

**5. Chat**
- AI와 함께 논문에 대해 토론하며 사용자의 궁금증 해소
- 지금 읽고 있는 섹션(PDF는 쪽 번호 포함)을 질문 맥락으로 자동 첨부
- Hallucination 방지를 위해 원문 위치 링크 또는 근거 표시 필수

**6. Smart Citation**
- 본문의 참고 문헌을 클릭하면 그 자리에 인용 카드로 제목, 저자, 학회·연도, 초록, 참고문헌 전체 표기를 즉시 확인
- 인용 카드에서 라이브러리에 보관, 원문(arXiv) 유무 확인, BibTeX 복사, 피인용 수 확인(Semantic Scholar) 가능
- 논문의 맥락을 파악해 인용한 이유와 읽을 가치를 설명
- 참고문헌 목록은 본문 인용 횟수 순으로 정렬하고 라이브러리 보관 여부를 표시

**7. Section Preview**
- 연결된 섹션(표, figure 등)이나 인용 문서를 이동 없이 바로 미리 보기로 확인

**8. External Link Explanation**
- 논문에 언급된 외부 리소스도 요약으로 간단히 확인

**9. AI Document Outlining**
- AI가 자동으로 논문의 아웃라인(목차)을 만들어 목차가 없는 논문도 구조적으로 파악하도록 도움
- 아웃라인에서 섹션을 누르면 해당 위치로 이동하고, 현재 읽는 섹션과 읽은 위치(%)를 표시

**10. Visualization**
- 논문 전체 또는 일부(논문에서 설명하는 기능이나 기법 등)의 작동 원리를 시각화
- 텍스트 선택 메뉴의 인포그래픽으로 선택한 부분을 시각 요약(흐름도, 방법/결과 정리 등)으로 생성
- 생성한 시각 자료는 이미지(SVG)로 vault에 저장하고 요약 MD에 첨부 가능

## II. 논문 추천 및 논문 DB 관리
기본적으로 Connected Papers, Research Rabbit의 방식과 유사한 방향으로 기능을 제작할 예정
https://www.connectedpapers.com/about
https://www.researchrabbit.ai/features

**1. Paper Library**
- 논문 원본(PDF 또는 arXiv HTML), Summary 파일을 저장하는 라이브러리
- 논문 추가는 PDF 파일 업로드 또는 URL 입력(arXiv URL이면 HTML 우선)으로 진행
- 왼쪽 사이드바에서 최근 열어본 논문, 검색, 읽음 상태별 보기, Research Field 태그, 휴지통으로 이동
- 태그로 Research Field와 Base Model을 표시
- 읽음 상태(읽을 예정, 읽는 중, 완료)는 자동으로 바뀌고(처음 열면 읽는 중, 끝까지 읽으면 완료로 표시할지 안내), 사용자가 드롭다운으로 언제든 직접 변경 가능
- 목록에서 요약 MD를 눌러 오른쪽 패널로 바로 미리 보기(이전/다음 논문 이동, 리더에서 열기)
- 여러 논문을 선택해 실험 설계 초안 만들기, BibTeX 내보내기 가능
- 라이브러리 전체를 대상으로 한 검색과 채팅 기능(화면 오른쪽 아래 "라이브러리에 묻기" 버튼, Hallucination 방지를 위해 인용 시 원문 위치 링크 또는 근거 표시 필수)
- 다운 받은 논문들과 Summary 파일은 서버의 Obsidian vault에서 관리

**2. Related Paper Graph**
- Semantic Scholar, OpenAlex, arXiv, OpenReview, DBLP, Papers with Code, Hugging Face, 주요 AI 학회(NeurIPS, ICML, ICLR, AAAI, CVPR, ICCV, ECCV, ACL, EMNLP, KDD)에서 연관된 논문을 추천
- 논문 주변의 선행·후속·관련 연구를 지식그래프 형태로 표시하고 Seed 논문과 각 논문의 유사도를 표시
- 인용 구조 기반(co-citation)과 임베딩 기반 의미 유사도를 통해 연구 동향과 계보를 따라갈 수 있도록 보조
- 지식그래프의 노드를 선택하면 해당 논문에 대한 간단한 요약 설명 표시, 사용자가 직접 논문 리딩의 필요성을 확인하기 위한 목적
- Related Paper Graph와 Paper Library를 연동해 이미 읽은 논문을 표시하고 그래프에서 바로 라이브러리로 논문 추가

**3. Experiment Replication**
- 논문에서 하이퍼파라미터, 데이터셋, 평가지표, 공식 코드 레포를 추출해 실험 설계 초안을 자동 생성
- 리더, 라이브러리, 실험 대시보드의 "새 실험 → 논문에서 재현 실험 만들기"에서 진입
- 실험 설계 초안 화면은 값 추출 → 검토·설계 → 프로젝트 생성 3단계로 진행
- 추출한 값 표에는 값마다 근거 링크와 상태(원문 확인 / 추정 필요 / AI 제안)를 표시하고, 추정 필요 값을 채워야 프로젝트 생성 가능
- 오른쪽 "Claude와 설계 토론" 패널에서 시작 방식(그대로 재현 / 내 데이터에 적용 / 하이퍼파라미터 스윕)과 Conda 환경(기존 환경 재사용 / 새로 생성)을 선택
- 생성될 파일 목록을 미리 보여준 뒤 프로젝트 생성
- Hallucination 방지를 위해 값마다 출처 위치 표시 필수

## III. 실험 자동화 및 관리
**1. Autonomous Experiment Design**
- AI와 함께 토론하며 로컬 환경에서 돌릴 실험을 설계
- 새 실험은 Claude와 토론하며 설계 / 논문에서 재현 실험 만들기 / 설정만 바꿔 큐에 추가 중에서 선택
- 설계한 실험에 대한 설명해주는 MD 파일 생성
- 실험 프로세스 시각화
- 사용자가 사전 세팅한 Conda 환경 또는 신규 Conda 환경 생성하여 실험 구동
- 설계한 실험에 부합하는 Conda 환경을 추천하고 사용자가 선택
- 선택한 conda 환경의 세팅 정보는 프로젝트 폴더 내 별도 파일로 저장

**2. Journal Automation**
- 각 실험 결과와 리뷰는 실험 폴더의 analysis.md에 정리
- 가설·결과·결정은 State.yaml, Experiment_log.csv, Decision_log.md, Failures.md에 갱신하여 세션이 바뀌거나 복구가 불가능해도 이어받도록 함
- CLAUDE.md는 고정 지침으로 유지하고, 변경이 필요하면 사용자 승인 후 수정

**3. Code Editor**
- 별도 프로그램(code-server 등) 없이 웹 UI 안에 직접 구현(Monaco Editor)
- 프로젝트 폴더 내 파일들을 VS Code처럼 확인하고 생성, 편집, 저장 가능
- VS Code와 같은 배치: 왼쪽 작업 표시줄(탐색기 / 검색 / 소스 제어 / 실험 실행), 가운데 편집기 탭과 하단 패널(문제 / 출력 / 터미널), 오른쪽 Claude Code 채팅
- 작업 표시줄에서 선택된 아이콘을 다시 누르면 사이드바가 접히고, 모든 패널은 경계선을 드래그해 크기 조절 가능
- 탐색기에서 새 파일, 새 폴더, 새로 고침, 모두 접기 가능
- 잠긴 파일(Evaluation.md, Config.yaml 등)과 읽기 전용 실험 폴더는 탐색기와 편집기에 표시
- AI가 수정한 내용은 편집기에 변경 표시와 함께 보여줌
- 소스 제어에서 커밋, PR 열기, 변경 내용과 커밋 그래프 확인
- 실험 실행 패널에서 새 실험을 작업 큐에 추가(기준 실험, 변경 파일, Conda 환경, 자동 커밋·새 브랜치 여부 선택)하고 큐 순서 변경·정지, 최근 실행 결과 확인
- 하단 터미널은 실행 중인 실험의 tmux 세션에 연결해 실시간 로그 확인
- Claude Code 채팅 입력창에서 현재 파일을 맥락으로 첨부하고 권한 프리셋을 바로 변경 가능

**4. Authority Adjustment**
- 실험과정에서 발생하는 의사결정에 대해 AI가 어디까지 대신할지 권한 설정 가능
- 의사결정 권한은 연구 전체 자동화(실험 결과에 대해 판단하고, 어떻게 개선할지도 자동으로 결정), 오류 대응 자동화(실험 과정에서 발생하는 에러 내역에 대한 수정만 자동화), 수동제어(모든 의사결정 수동 승인)
- 권한 프리셋은 권한 설정 화면, 코드 에디터의 Claude Code 입력창, 모바일 화면에서 변경 가능하며, 실행 중인 실험에는 적용하지 않고 다음 작업부터 적용, 변경 내역은 Decision_log.md에 기록
- 의사결정 권한이 연구 전체 자동화일 경우 종료조건(목표나 최대 실행 횟수, GPU 시간, 에이전트 사용량, 마감 시점 기준)을 사용자에게 물어보고 실행하기
- 의사결정 권한은 행동 유형별(코드 수정 / 하이퍼파라미터 변경 / 패키지 설치 / 파일 삭제 / 새 실험 시작 / 외부 네트워크 접근) 옵션도 사용자가 자동 허용 / 승인 필요 / 차단 중에서 직접 선택 가능
- 프로젝트 폴더 밖 쓰기·삭제, 실험 진행 중 종료 조건·Evaluation.md 수정, 이전 실험 폴더 덮어쓰기는 잠긴 항목으로 프리셋과 관계없이 항상 차단
- 선택한 권한은 Hooks로 강제하며, 승인이 필요한 행동은 Claude Code 권한 승인 창(허용 / 거부 후 다른 방법 지시)으로 선택
- 승인 필요로 설정한 행동은 "앞으로 계속 허용"을 선택하더라도 Hooks에서 매번 다시 승인 요청
- 실험 결과에 따른 다음 방향 등 연구 의사결정은 선택지 형태로 제시하고 사용자가 선택
- 모든 승인·거절·선택 내역은 Hooks로 별도 로그 저장
- 연구 전체 자동화의 루프 반복과 종료 조건 판정은 시스템이 담당
- 사용자에게 받은 종료 조건은 specifications/Config.yaml에 저장하고, 사람이 읽는 설명은 docs/Stop_and_recovery.md에 기록
- 실험 진행 중 AI는 종료 조건을 수정할 수 없으며(Hooks로 차단), 실험이 중단된 상태에서만 사용자 승인(권한 승인 창)을 거쳐 AI가 수정하거나 사용자가 직접 수정 가능
- 프로젝트 폴더 밖 쓰기 및 삭제 금지, 패키지 설치나 외부 네트워크 접근은 별도 승인
- NaN loss, 발산, OOM 반복, 디스크 부족 시 자동 중단 후 사용자에게 Discord 웹훅 알림 전송

**5. Decision Recommendation**
- AI가 실험 결과에 대한 리뷰 진행
- 진행한 실험 결과에 대해 어떻게 대응할지 추천

**6. Git 및 파일 버전 관리**
- Github Repo를 연결해 실험 코드 관리
- AI가 진행한 의사결정에 따른 수정내역을 git에 PR, commit, push하여 수정내역 백업
- 실험 기록(실험 폴더, logs/, state/)은 권한 단계와 성공 여부에 관계없이 항상 main에 직접 반영
- 코드 변경은 실험별 브랜치에서 PR로 관리하며, 수동제어와 오류 대응 자동화에서는 사용자가 병합, 연구 전체 자동화에서는 성공 기준을 충족한 실험만 자동 병합
- 병합되지 않은 실험 브랜치는 삭제하지 않고 보존하며, Experiment_log.csv에 각 실험의 브랜치명과 커밋 해시를 기록
- `data/`, 각 실험의 <output>, 체크포인트, 모델 가중치, `wandb/` 폴더 등 push 실패를 유발할 수 있는 대용량 파일은 gitignore에 자동으로 추가
- 실험 폴더의 config.yaml, result.csv, analysis.md, 코드 파일 등 실험에서 중요한 요소들은 commit 항목에 포함
- 각 실험별로 나눠서 commit을 진행하고 프로젝트 폴더 안에 개별 실험 폴더를 생성하여 관리
- 1 프로젝트 1 repo를 원칙으로 git에서 관리
- README.md에 실험 개요, 모델 아키텍처, 각 실험 결과를 요약하여 정리
- 실험 설계 시 프로젝트 폴더 내 file directory 구조는 첨부한 `Loop Engineering을 활용한 실험 설계.pdf` 파일 참고, 해당 pdf에서 AGENTS.md의 구조는 똑같이 가져가되, 파일명은 CLAUDE.md로 사용, 각 파일명의 대소문자 표기법은 통일해서 오류 방지, conda 환경 정보는 specifications/environment.yml에, 승인·거절 로그는 logs/Approval_log.csv에 넣기

## IV. 원격 모니터링 시스템
- 원격 접속중이 아니더라도 세션이 중단되지 않고 작업중인 실험은 계속 진행
- 자연어(채팅)로 실험 실행 명령을 줄 수 있고, Claude Code CLI가 실험을 제어
- Experiment_log.csv와 Decision_log.md는 단계와 상관없이 항상 기록하고, 권한 단계는 승인 로그의 내용만 달라지게 제한
- 실시간으로 모바일 반응형 웹 UI를 통해 CLI에 올라온 진행 현황(잔여 시간, Epoch 진행률, Loss 값, accuracy 등), 진행중인 실험에 대한 현황 통계 자료, 자원 현황(GPU 사용률, VRAM, 온도, CPU, RAM, 디스크 등)을 가독성 있게 확인
- 실험 대시보드에는 승인 대기, 진행 지표(진행률, Val accuracy, 이번 최고, 목표까지, 남은 GPU 시간), 학습 곡선, 자원, 실험·큐 표, 결정·이벤트 기록을 표시하고, 실시간 터미널 로그는 대시보드가 아닌 코드 에디터 하단 터미널에서 확인
- 대시보드에서 루프 일시정지 가능
- 모바일 화면은 하단 탭(논문 / 실험 / 코드)으로 구성하고 확인과 요청 위주로 제공
  - 실험: 승인 대기(Claude 앱으로 이동), 진행 현황과 학습 곡선, 주요 지표, 큐와 최근 결과, 결정·이벤트, 권한 프리셋 변경, 루프 일시정지, 실험 정지(확인 후 체크포인트 저장하고 정지, 큐는 유지)
  - 논문: 검색, 읽음 상태별 보기, 요약 확인과 읽음 상태 변경, 라이브러리에 묻기(논문 읽기와 하이라이트는 PC 리더에서)
  - 코드: 실험 브랜치의 변경 내용(diff)과 커밋 기록 확인, PR 열기, Claude Code에 요청(코드 편집은 PC에서)
- 원격 웹 UI에는 인증 시스템 구축하여 보안 확보
- 비정상 종료 시 복구를 위한 모델 학습 체크포인트 생성하고 별도의 보존 요청이 있지 않는 한 실험이 끝나면 재개용 체크포인트는 자동 삭제, 최종/best 모델은 보존
- 비정상 종료 시 시스템 복구와 작업 큐를 이어받아 재개, 자동으로 claude remote-control 재연결하여 중단된 세션 복구
- 재연결이 불가능하면 State.yaml 기준으로 새 세션에서 다음 루프부터 재개
- 루프 도중 중단된 실험은 학습 체크포인트가 있으면 이어서 진행하고, 없으면 실패로 기록한 뒤 새 실험 폴더에서 다시 실행
- 완료 알림, 이상 감지, 에러 등 시스템 이벤트는 Discord 웹훅으로 알림
- 권한 승인과 의사결정 선택이 필요한 사항은 Claude 앱 푸시 알림으로 받고, Claude 앱 또는 claude.ai 웹에서 원격 승인

## V. 구독중인 툴과 AI Agent 연결
- 사전에 Claude Code CLI 설치 필요
- Claude 앱 푸시 알림을 위해 Claude Code /config에서 권한 요청 시 푸시(Push when actions required) 활성화 필요
- Discord 웹훅으로 시스템 이벤트 알림 전달, 웹훅 URL과 알림 기능은 프로젝트 폴더가 아니라 이 원격 실험 시스템 관련 파일에서 관리(gitignore 처리)
- 장시간 자율 실행 중 AI Agent가 한도에 걸리면 AI의 의사결정만 일시정지 후 Discord 웹훅으로 한도 도달 알림 전송, 사용자가 추가 사용량을 직접 확보하거나 한도가 풀릴 때까지 대기했다가 재개(시스템이 추가 사용량을 자동 구매하지 않음)
- W&B 연결 가능, API 키를 받아와서 입력하면 실험 설계 시 API 키 환경변수(gitignore 처리)로 자동으로 입력됨

## VI. 웹 UI 구성
- 상단 메뉴는 논문 · 실험 · 코드 순서로 구성하고, 화면 전체 폭을 사용
- 논문: 라이브러리(목록) → 리더(논문 하나)
- 실험: 왼쪽 사이드바에서 프로젝트를 고르고 대시보드와 권한 설정을 전환(권한은 별도 상단 메뉴 없이 실험 안에 포함), 실험 설계 초안은 새 실험 메뉴에서 진입
- 코드: VS Code 배치의 코드 에디터
- 모든 화면의 사이드바와 패널은 경계선 드래그로 크기 조절, 사이드바는 접고 펼치기 가능(키보드 화살표로도 조절)
- 디자인은 흰 배경, 청록(#0E6E5C) 강조색, 승인 대기·확인 필요는 주황 계열로 통일하고, 글꼴은 Noto Sans KR과 Roboto Mono 사용
